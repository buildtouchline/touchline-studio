# User-provided `132877_2nd.json`: bounded provenance and suitability audit

> **Publication note:** The 2.6 GB source JSON, extracted GSR records and preview images are excluded from this PR. This report records provenance and why GSR projected boxes were not used as detection ground truth.

Read-only local source: `/Users/jaivinush.c/Downloads/132877_2nd.json`, 2,776,419,619 bytes, SHA-256 `9f9c3a781820cc5fbe872cf8c2901fbe892f02c0ed1050156305006578d259a0`. The user supplied its [Hugging Face `main/gsr/132877` source URL](https://huggingface.co/datasets/atomscott/soccertrack-v2/tree/main/gsr/132877). A live Hub filesystem `stat` returned the same 2,776,419,619-byte size for `gsr/132877/132877_2nd.json`; a live listing returned 3,419,930,605 bytes for `videos/132877/132877_panorama_2nd_half.mp4`, matching the local video size. These size matches and the supplied URL support source identity, but the connector did not expose remote file hashes, and `main` can change. The local JSON was not copied or uploaded. The file is too large to load with `json.load` on this 8 GB machine; `inspect_external_gsr.py` used a memory-mapped bounded extraction of **only the 12 already frozen panorama frames** into `external_gsr_132877_subset.json`. The original 24-frame benchmark manifest, predictions and `annotations.json` were not changed.

## What the file contains

The header identifies `CLPD-132877-2nd`, GSR format version `1.3`, 25 FPS, 69,350 frames, 4096×1084 image entries and 2,774-second clip timing. For each selected source frame index `k`, the file's image entry uses one-indexed `file_name=(k+1).jpg` and image ID `3920` plus six-digit `(k+1)`; this matches the frozen frame indices and dimensions. All 12 selected entries say `is_labeled=true`. Each extracted frame has one pitch-line record, 20 player records and two goalkeeper records. Across those 12 frames, 35 distinct GSR `track_id` values appear. Object records have a role, track ID, `bbox_image`, and pitch-space bottom-middle coordinates; the 264 extracted pitch points range from x = −42.00 to 51.45 and y = −30.60 to 24.48 in the declared metric coordinate system. These are **source-file records**, not Touchline measurements or manual image-box labels.

Three `bbox_image` proxy overlays (`external_gsr_preview/`) were generated on the frozen source PNGs for visual alignment inspection. Some proxy boxes lie near on-field players. They do **not** cover every visible human in the images; for example the visible person by the near right touchline in the late frame is outside the 22 GSR player/goalkeeper records. The overlays are labelled `NOT detection ground truth` and were not imported into `annotations.json`.

## Why this does not unblock detection IoU scoring

The [SoccerTrack v2 GSR format guide](https://github.com/AtomScott/SoccerTrack-v2/blob/main/docs/format-gsr.md) explicitly says the main GSR release has **no ground-truth detections** and that `bbox_image` must not be used for image-space scoring. The [dataset paper](https://arxiv.org/abs/2508.01802) explains that full bounding-box labelling was not completed for the main release; GSR positions derive from synchronized BePro system data, while a separate curated MOT subset has bounding-box ground truth. Therefore the provided GSR JSON cannot replace the human-reviewed, every-visible-person boxes required by this Level 3 detection benchmark. `metrics.json` and `metrics_batch.json` correctly remain blocked, with zero reviewed frames.

## What it may support later

The GSR track IDs and pitch coordinates may help review **game-state tracking or a separate external positional comparison**, after confirming exact video/JSON release alignment, annotation provenance, and the intended role/visibility scope. The [dataset v1.2 change record](https://huggingface.co/datasets/atomscott/soccertrack-v2/blob/main/CHANGES_v1_2.md) says v1.2 corrected an approximately one-second synchronization problem for match 132877 and that frame k then matches video frame k. It also says v1.2 assigned second-half `info.id=920` and `image_id` prefix `3920`, both present in the local file; this is strong structural evidence of v1.2-or-later GSR content. The local MP4's stream starts at PTS 1.000 s, also listed in that change record; the frozen frame manifest uses time from the first decoded frame. The local JSON header's `1.3` is the **GSR schema version**, not the dataset release number. The user's URL points to mutable `main` and the file sizes match, but exact paired content hashes and an immutable revision are not yet established. `bbox_pitch` values are vendor-derived position annotations; their independence and error from Touchline's future calibration would need explicit evaluation before treating them as a physical reference.

The v1.2 change record specifically says M10's `bbox_image` values are **regenerated by projecting pitch positions through released camera intrinsics and a smooth box-size model**, rather than being drawn by hand. It also notes player positions are rounded to a 1.05 m × 0.68 m grid. These details reinforce that image-box IoU scoring and fine-grained speed claims would be inappropriate from this GSR file.

The maintainer's [dataset licence](https://github.com/AtomScott/SoccerTrack-v2/blob/main/LICENSE-DATA) says CC BY 4.0 with attribution, while the [Hugging Face dataset page](https://huggingface.co/datasets/atomscott/soccertrack-v2) requires contact-sharing access conditions. These sources support local research analysis of the user-provided file; publication or demo use of the footage and derived frames should be checked against the exact access terms and team authorization.
