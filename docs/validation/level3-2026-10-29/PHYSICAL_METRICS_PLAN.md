# Level 2 physical-metric validation gate

> **Publication note:** This is a prerequisite plan from the local experiment. It does not contain surveyed calibration, independent movement measurements, or a field validation result.

**Current state: blocked by evidence, not by arithmetic execution.** Every preserved Level 2 run's `analytics.json` reports calibration `unavailable` and zero confirmed players. The two videos and the Level 3 manifest contain source geometry and PTS, but this inspected artifact set has no surveyed pitch coordinate map, independently checked calibration, reviewed player-identity trajectory, or independently measured reference movement. Synthetic test fixtures in `tests/test_calibration.py`, `tests/test_metrics.py` and `tests/test_analytics.py` demonstrate code behavior, not field accuracy.

The later user-provided `132877_2nd.json` adds SoccerTrack v2 GSR pitch-space trajectories and player IDs for the panorama (see `EXTERNAL_GSR_AUDIT.md`). Those positions are derived from the BePro provider system; they are a **candidate external comparison**, not a surveyed Touchline camera calibration or documented independent error bound. Release v1.2 changed match 132877 timing by roughly one second. Verify paired immutable file revisions and alignment before any positional comparison. The GSR `bbox_image` field is not detection ground truth.

The code path is `pipeline.py` detections → `IoUTracker.update` → observations with original frame PTS/time → `analytics.py` bottom-center box contact points → `metrics.py` `Calibration.project` → distance/speed/activity/intensity summaries. `Calibration` validates a finite invertible 3×3 mapping, image bounds, validity interval and nonempty `independent_check_ref`; it also exposes a source-geometry compatibility method, but the inspected pipeline does **not** call that method. `movement_summary` further requires review-reference strings at both ends, a continuous segment and gap ≤0.75 s; it excludes gaps and out-of-region points. Distance is summed along eligible projected segments; average speed is distance over eligible time, and windowed speed needs a fully covered window. Activity and intensity use declared speed bands. Intensity high-speed time/distance are not validated discrete sprint counts. Studio's upload route defaults to uncalibrated mode and rejects an unverified calibration mode; the old synthetic dashboard path is blocked. These are gates and estimates, not measured field accuracy.

**Additional source-code concern:** `analytics.py:119` manufactures `identity_review_ref=f"track_rev_{track_id}"` for every track observation. Since this is not a human review record, supplying a valid-looking `Calibration` could allow metric arithmetic to proceed despite unreviewed tracker identity. Treat real-footage physical metrics as unavailable until that path is corrected and separately tested. Do not assign a fake reference to make a run pass.

`Calibration.check_geometry_compatibility` is defined at `metrics.py:104` and covered by unit tests, but `rg` found no production caller; `analytics.py` also constructs `Point` without a geometry revision. A supplied calibration could therefore be applied to mismatched source dimensions or revised geometry unless the caller checks externally. `independent_check_ref` is only a nonempty string in the inspected code, so its existence does not prove that an independent survey artifact exists. These are further gates before real-footage physical metrics can be advertised.

## Smallest viable field experiment

1. Select one short fixed-camera interval with unchanged 4096-wide source geometry. Record video hash, source PTS/time range, lens/crop/rotation state and camera position. A wide panorama may not fit one homography across the whole image; measure held-out residuals and restrict the valid region or correct geometry if necessary.
2. Obtain genuinely measured pitch landmarks with world coordinates in metres and pixel locations for the **fit set**. Keep at least one independently surveyed landmark or distance out of the fit. Record survey method, uncertainty, reviewer and immutable source reference. Compute a calibration only for the verified geometry and time interval.
3. Independently annotate ground-contact positions and stable person identity across a short movement segment. Record occlusion/no-detection states, source indices and PTS. Do not infer identity from `local_track_id`.
4. Obtain independent reference distance/time for that person's path, not derived from the same fitted homography or model boxes. Predeclare acceptable reprojection, distance and speed errors before viewing results.
5. Run the pipeline in a separate output directory with the evidence-backed calibration and corrected identity-review path. Compare predicted versus reference distance/speed, report absolute and relative error, eligible coverage versus excluded time, and all exclusion reasons. If fit or held-out checks fail, report calibration invalid and retain pixel-space output. Do not advertise sprint events from speed-band exposure.

The next acceptance gate is an evidence package containing fit and held-out landmark coordinates with independent survey provenance, a geometry-valid calibration with measured residuals, a human-reviewed trajectory/identity ledger, a separate movement reference and a reproducible command/result record. Without these, no metres, metres per second, sprint or intensity accuracy claim is supportable.
