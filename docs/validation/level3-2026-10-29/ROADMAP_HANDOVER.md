## 3. Level 2 physical metrics — blocked

All 12 inspected Level 2 `analytics.json` files report calibration `unavailable` and zero confirmed players. No surveyed pitch mapping or independent movement reference was found in the inspected run artifacts or Level 3 manifest. The code uses original frame PTS, box bottom-center contact, a 3×3 `Calibration`, distance over eligible projected segments, speed and speed-band activity/intensity. Without calibration, the saved output suppresses metres and metres-per-second. Synthetic unit fixtures are not field validation.

The newly supplied GSR JSON includes vendor-derived pitch coordinates. They may support a separate positional-reference study, but they do not supply Touchline's camera calibration or a documented independent survey/error bound. The dataset card says release v1.2 corrected an approximately one-second timing offset for match 132877; the file came from mutable `main`, and the live connector exposed sizes but not paired content hashes. Confirm an immutable paired revision before interpreting per-frame position differences.

Additional code gates remain: `analytics.py:119` manufactures identity-review references; `metrics.py:104` defines a geometry compatibility check but no production caller was found, and analytics points have no geometry revision; `independent_check_ref` is only checked for a nonempty string. `PHYSICAL_METRICS_PLAN.md` specifies the smallest viable experiment: independently surveyed fit and held-out pitch landmarks, fixed source geometry/time validity, a reviewed person trajectory, a separate measured movement reference, predeclared error tolerances, and error/coverage reporting. No physical test was run because these prerequisites are absent. Do not create a synthetic calibration to satisfy the code gate.
